# Z's Multi Tool Marketplace

Official marketplace repository for **Z's Multi Tool**.

This repository hosts downloadable modules for Z's Multi Tool. The application reads the marketplace index from GitHub and allows users to browse, download, install, and update modules directly from the app.

## Marketplace URL

The Z's Multi Tool client uses:

https://raw.githubusercontent.com/Zyvelia/zmt-marketplace/main/index.json

## Repository Structure

```text
zmt-marketplace/
├── index.json
├── packages/
│   ├── module-id/
│   │   └── build-1.zmod
│   ├── another-module/
│   │   └── build-1.zmod
│   └── ...
└── README.md
index.json

The marketplace index contains the information Z's Multi Tool uses to discover available modules.

It contains information such as:

Module ID
Module name
Description
Version
Author
Publisher
Package location
Other module metadata
packages/

This directory contains the actual .zmod module packages.

Each module should have its own directory:

packages/
└── my-module/
    └── build-1.zmod
Installing Modules

Users do not need to download .zmod files manually.

From Z's Multi Tool:

Open Marketplace.
Refresh the marketplace.
Find a module.
Download/install the module.
Restart or reload the application if requested.

The client downloads the module package directly from this repository.

Publishing Modules

Marketplace packages are generated by the Z's Multi Tool developer tools.

A published marketplace normally contains:

PublishedModules/
└── marketplace/
    ├── index.json
    └── packages/
        └── your-module/
            └── build-1.zmod

After building/publishing a module, the marketplace contents can be pushed to this repository using the marketplace publishing script.

The publishing script replaces the repository's marketplace contents with the local marketplace contents and pushes the changes to the main branch.

Updating the Marketplace

When a module is updated:

Build the new module package.
Update the marketplace index.json.
Place the new .zmod package in the appropriate packages/<module-id>/ directory.
Run the marketplace publishing script.
Push the changes to GitHub.
Users can refresh the Marketplace inside Z's Multi Tool.

No GitHub Release is required for marketplace modules.

Module Packages

Modules are distributed as .zmod packages.

A package contains the files required for Z's Multi Tool to install and load the module.

The marketplace keeps the package files separate from the main Z's Multi Tool application.

This means the main application does not need to ship with every available module.

Authors and Publishers

A module's author and publisher may be different.

Author

The author is the person or organization that created the module.

Publisher

The publisher is the person or organization that submitted/published the module to the marketplace.

Marketplace metadata should preserve both when applicable.

Main Application vs Marketplace

The Z's Multi Tool project uses separate repositories for the application and marketplace.

Z's Multi Tool

The main application repository contains:

Z's Multi Tool source code
Application builds
Installers
Application releases
ZMT Marketplace

This repository contains:

index.json
.zmod module packages
Marketplace metadata

Keeping these separate allows modules to be updated without releasing a new version of the main application.

For Developers

To create a module for Z's Multi Tool, use the module-development tools/documentation provided by the main project.

A module should provide the required Z's Multi Tool module entry point and metadata expected by the application.

Once a module has been packaged as a .zmod, it can be submitted to the marketplace.

Repository Rules

Please keep the following structure intact:

index.json
packages/

Do not rename index.json unless the Z's Multi Tool client is updated to use a different location.

Module packages should remain inside:

packages/<module-id>/
License

The license for each module is determined by its author and/or the module's included license information.

The marketplace repository itself does not automatically change the license of individual modules.
